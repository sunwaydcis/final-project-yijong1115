# AI Integration Reflection

AI was integrated throughout this project under the Tier C policy. I used ChatGPT mainly during the earlier planning and implementation stages, while Codex was used later to review the existing project, diagnose logical problems and make verified changes in the repository. Instead of requesting the whole application at once, I worked feature by feature. My prompts focused on specific tasks such as designing the `FoodItem` hierarchy, creating a generic repository, validating inventory data, connecting ScalaFX forms and implementing the distribution workflow. This made the suggestions easier to understand and evaluate.

The most useful benefit of AI was the support it provided when translating requirements into a structured design. It suggested ways to separate models, repositories, services and user-interface classes, while still following the Scala 3 style used in the lecture slides. AI also helped explain unfamiliar technical areas such as Derby transactions, safe JDBC resource handling and ScalaFX controls. During debugging, it helped identify the UTF-8 BOM problem, distribution over-allocation risks and the need to deduct stock exactly once. This saved time, but I still had to understand how each suggested change affected the rest of the application.

AI output was not treated as automatically correct. Some earlier suggestions produced a workflow where distribution statuses could be changed without updating inventory. Later review also found that the report labelled completed request IDs as unique households and that the dashboard added quantities with incompatible units. These issues showed that code can compile while its business meaning is still incorrect. I discussed the problems, compared the suggestions with the required workflow and accepted revised solutions that used reservations, transactions and more accurate labels. I also chose to keep automatic storage instructions and use a fixed list of inventory units because those decisions made the interface clearer.

To use AI responsibly, I recorded significant interactions in `ai/interaction_log.md` and linked assisted source sections using `// ai-assisted: #N` and `// why:` comments. I reviewed changes through Git diffs, compiled the project and ran MUnit tests. I also tested the main workflows manually, including adding food, approving or rejecting requests, creating plans, completing distributions and confirming that data remained after restarting. When suggestions did not match the intended behaviour, I requested corrections instead of accepting them unchanged.

Overall, AI acted as a development assistant and reviewer rather than replacing my decisions. It helped me work through a larger project incrementally, but the experience also taught me to question generated code, verify business logic and keep evidence of how assistance was used. In future projects, I would continue using AI for explanations, targeted reviews and test ideas while remaining responsible for the final design, validation and correctness of the submitted work.
